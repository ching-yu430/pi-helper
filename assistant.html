③ 現場共通準則
不知道 IP，也解析不到 .local
  1. 免查 IP 流程失敗後，先完成上方 .local 檢查；確認重試仍失敗，再請助教帶著做下列步驟。
  2. 執行 ipconfig，查看 Wi-Fi 的 IPv4、遮罩、閘道。若只有 169.254.x.x，重新連熱點。
  3. 手機若有裝置 IP 清單就使用；沒有此功能就跳過，不預設手機品牌。
  4. 執行 arp -a 查看已知鄰居。它不是完整裝置清單，也無法證明哪台是 Pi。不要把筆電自己或預設閘道當成 Pi。
  5. 在 Windows 開啟 Advanced IP Scanner，按「IP」選目前 Wi-Fi 網段再 Scan。名稱／製造商僅作辨識線索，沒有可信依據時不要任選候選 IP。
  6. 若仍找不到，核對刷機設定、熱點密碼與供電；可將熱點切為 2.4 GHz，再測試。若改了熱點名稱或密碼，須與 Pi 原設定一致。
沒有可辨識的 IP 時，無法僅憑 Windows 判定是 SSH 未開還是 Pi 未連網。不要猜固定網段，也不要因 arp 清單空白就認定刷機失敗。


SD 卡啟用 SSH（不用螢幕）
  1. 適用本課堂 Raspberry Pi 5 的標準 Raspberry Pi OS 桌面版，且已建立帳號。若可透過其他方式正常關機，先正常關機；完全無法登入時，等待寫入活動停止後斷電，仍有檔案損壞風險。
  2. 拔除電源後取出 microSD，插入 Windows 讀卡機，開啟可讀的 bootfs 分割區。
  3. 在根目錄建立空白檔案 ssh，不加副檔名。開啟檔案總管「顯示副檔名」確認。
  4. 安全移除 SD 卡，插回 Pi、供電，等開機後重新取得 IP，再測試 TCP 22。
ssh 檔案只啟用 SSH，不會修正 Wi-Fi、建立帳號或重設密碼。Windows 若要求格式化另一個分割區，請取消。


何時才重刷？
先排除連錯熱點、IP 錯誤與主機金鑰衝突。若帳號／Wi-Fi／SSH 設定都無法確認，而且尚無需保留成果，可重新燒錄建立一致設定。
重刷會清除 SD 卡內容。已有作業成果，先備份再處理。
  • Imager 裝置：Raspberry Pi 5；OS：Raspberry Pi OS 64-bit 有桌面版本，不選 Lite。
  • Hostname：依本頁選定組別（例如第 1 組為 pi5-01）。
  • 建立正確帳號與密碼；不要預設預設帳號存在。
  • Wi-Fi：該組熱點名稱、密碼、國家 TW。
  • 啟用 SSH，課堂若用密碼登入，就選密碼驗證。
  • 寫入並驗證完成，確認套用自訂設定。
