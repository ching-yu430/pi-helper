# Python 與 USB 拍照課程

第一版教材包含八個階段：確認操作位置、建立資料夾、hello.py、寫入文字檔、安裝與環境檢查、預覽拍照、照片品質整理、Windows 下載。學生已能使用遠端桌面；本次不需要重刷或重做 SSH。

## 版本與實測範圍

依老師提供的測試紀錄，pi5-10 的 GENERAL WEBCAM 使用 uvcvideo，可從 /dev/video0 以 MJPEG 預覽與拍照；曾成功儲存並開啟 1920×1080 JPG。商品自動對焦、原生感光元件解析度與長時間 30 FPS 尚未確認；6.18.50 不作為 OS 版本。

本儲存庫的 `courseware/camera_app.py` 是根據上述行為新寫的課堂介面，**不是先前已實測的 camera_test.py 原始碼**。Tkinter、遠端桌面介面、重新連接與本機回報整合尚需現場 Pi 5 驗收。持續 1080P 取像、辨識、串流未加入正式流程。新課程在資料庫升級後預設關閉，由老師驗收後開放。

測試機 pi5-10 不應寫進正式九組。可先在該機以本機模式測試程式；要測完整雲端流程，請建立獨立測試課堂並開放對應測試組別，不增加正式課堂的組數。

## 老師／助教設定

1. 有 Supabase 管理權限的老師執行最新 [supabase/install.sql](../supabase/install.sql)，包含 `014_camera_course.sql`。沿用目前課堂，不重建課堂。
2. 工作台登入，在「課堂設定 → Python 與拍照：課程工具設定」選組、產生課程回報設定碼。這個設定碼與先前的背景設備回報碼不同，不能混用。
3. 在本組 Pi 的 user 帳號，用頁面上的三行指令依序下載 `pi_course.py`、`camera_app.py`，再執行 setup。整行前面不要加 sudo。
4. setup 詢問時貼上設定碼、按 Enter。輸入不顯示。主機名稱必須符合配對組別。憑證存於 user 的 `~/.config/pi-helper-course/config.json`，權限 0600。
5. 在 user 的家目錄執行 location，回看板確認收到本組紀錄。這項操作會回報目前 RFC1918 區域網路 IPv4，僅助教 API 回傳，學生 API 不回傳 IP。
6. 在真實 Pi 先完整驗收下列流程，再到「教材開放」勾選「Python 與 USB 拍照」。老師上課模式可以選擇八個階段，學生按「跟上老師進度」進入指定階段。

設定後會建立短指令 ~/pi-course；它使用 /usr/bin/python3 執行課程工具與學生程式。課程工具用 user 執行學生程式；只有更新／安裝套件時，會互動執行固定的 sudo apt 指令。它沒有開放任意遠端指令，也不錄製 shell 的所有操作。既有背景設備服務維持原本權限，不讀取學生家目錄或執行學生程式。

## 八階段的操作方式

各組在首頁選組後進入 camera.html。每步標示操作位置、當前動作、預期結果及錯誤處理。每個複製按鈕只複製一行指令。

學生的多行指令一次只顯示一行，做完再按「換下一行」。複製後會持續顯示貼上位置：Windows PowerShell 用 Ctrl＋V，樹莓派桌面終端機用 Ctrl＋Shift＋V，再按 Enter。程式碼需在樹莓派文字編輯器輸入、存檔；綠色按鈕複製的才是終端機指令。「換下一行」只切換說明，不會新增設備驗證或完成紀錄。

- 位置／資料夾：先親自練習 hostname、pwd、ls、mkdir、cd，再用 location／folders 檢查。工具不會替學生建立課程資料夾，資料夾存在也不代表學生已理解指令。
- hello.py：學生在文字編輯器親手輸入、修改並儲存，工具用 `/usr/bin/python3` 執行。程式正常結束且輸出包含本組名稱才通過。
- write_note.py：學生親寫文字檔程式；檢查 `message.txt` 是否在本次執行重新產生／寫入，且包含本組名稱。只有舊檔案不會通過。
- 環境：用系統 Python 與 apt 的 v4l-utils、python3-opencv、python3-tk。沒有加入 pip OpenCV 或 Pi 虛擬環境。Windows 辨識環境留待後續。
- 拍照：camera-install 取得統一程式，camera 啟動滑鼠介面。要求 1280×720 MJPEG 預覽、拍照時關閉重開並要求 1920×1080，約兩秒內保留最後成功影格，儲存 JPG，再回預覽。預覽、照片與正常結束必須來自同一次執行才整階段通過。
- 品質：可讀與尺寸正確屬技術驗證；清楚、曝光、構圖與物品完整性由學生親眼確認。新照片回報後，舊的品質確認會清除，必須重新查看。
- 下載：在 Windows PowerShell 執行本組 scp 指令，到下載資料夾開啟照片。此段尚待實測，需確認重複下載的目錄層級及同名檔案處理；不能只靠 Pi 宣稱 Windows 下載成功。

檔名為 `pi5-03_practice_日期_時間_微秒_隨機碼.jpg`，每張唯一、不覆蓋舊照片。目前類別為「練習拍照」，不預設正式物料類別、標註規則或模型。

MJPEG 的 `Corrupt JPEG data` 警告會保留在本機終端機，程式另外回報累計警告次數，不上傳完整日誌。存檔成功不等於沒有警告，也不等於照片視覺品質正常。640×480 YUYV 只列為後續對照測試，不聲稱已驗證。

## 回報與狀態判讀

事件含課程任務、本次 run ID、單調遞增序號、開始／通過／失敗／中斷狀態，以及限定欄位的檢查結果。網站用伺服器收到時間標記，不把裝置時間當作可信完成時間。

簡單程式輸出只在本機顯示，不上傳完整原始碼或 stdout；上傳是否包含本組名稱、結束碼等檢查結果。相機僅回報照片檔名、尺寸、大小、是否可讀與警告次數；**不自動上傳照片、縮圖或相機畫面**。兩個介面的縮圖用途不同：Pi 拍照介面顯示本機縮圖，網頁只接收驗證資訊。

每個步驟分開顯示設備驗證與學生自行確認。通過紀錄是上次檢查結果，不保證檔案與設備之後沒有改變；修改後要重新執行。整體完成由學生在照片品質與 Windows 下載確認後記錄。老師指定／重新開啟已完成課程，不會自動新增成功紀錄。

長時間 apt 工作每 30 秒回報仍在執行；超過 90 秒未收到後續狀態只能標示待確認，不判定卡死或關機。網路失敗時保留有限的本機待送事件，依序重試，伺服器忽略重複與較舊的序號。未送出的事件可能在下次執行工具時補送；也可明確執行：

```sh
~/pi-course flush
```

保留最近最多 128 個待送事件；大量離線操作可能失去較舊的中間紀錄。網頁不會把離線未收到的結果標成已驗證。必要時可明確使用手動確認繼續，標籤保留「未設備驗證」。

「清除看板與求助紀錄」清的是學生回報與求助，不重設設備／課程驗證。課程工具設定重新配對會撤銷舊憑證、重設本組雲端驗證紀錄；Pi 的照片與學生程式保留。同一個設定碼重跑 setup 會保留本機序號與待送事件。

## 現場驗收清單

- [ ] 補記 Pi OS、架構、系統 Python、OpenCV 版本；確認 apt 套件可安裝，Tkinter 在遠端桌面可開啟。
- [ ] pi5-10 本機測試與正式九組分開，主機與設定碼交錯時會停止設定。
- [ ] 學生真的建立資料夾、親寫與修改程式；錯組輸出、語法錯誤、只有舊文字檔時不能通過。
- [ ] 相機接在 Pi；找出可取像節點，預覽實際尺寸與照片實際尺寸分開確認。
- [ ] 連續預覽、多次拍照、滑鼠與 S／Q、縮圖、唯一檔名、正常結束後重新啟動都可用。
- [ ] 相機占用、斷線、沒有影格、尺寸不符與存檔失敗時保留介面且能重試，結束後裝置可供下一次使用。
- [ ] 核對每張原始照片；記錄 MJPEG 警告與可見破圖情況。必要時另外測 640×480 YUYV，不假設等同 1080P 品質。
- [ ] 實際 Windows 下載、重複下載、開啟照片測試成功，再允許學生自行確認該階段。
- [ ] 斷網、恢復、補送、重複送出與憑證重設不使舊結果覆蓋新結果；確認學生 API 沒有 IP 與憑證。
- [ ] 老師指定八個階段、手機操作、求助接手與投影畫面都由現場人員確認。

自動測試包括隔離資料庫、真實 Python 程式執行、合成影像 JPG 編解碼及瀏覽器流程；它們不能代替真實 USB 相機、Pi 5、Tkinter／遠端桌面與 Windows scp 驗收。
