# Python、AI 與 USB 拍照

學生進入課程時，先用六個小步驟連回本組 Pi：開啟熱點與電源、Win+R、貼上本組 mstsc 指令、確認目標、登入、開啟 Pi 終端機。已在 Pi 桌面的學生可直接跳到終端機確認，再接回原課程進度；工具選單可重新開啟連線教學。每步標明 Windows 或 Pi，常見錯誤收在「畫面不一樣／連不上？」；確認按鈕不代表設備驗證成功。這項網頁更新不需更新 SQL 或重裝 Pi 工具。

本課重點是取得可供辨識的照片；程式由學生依功能清單使用 AI 製作，不要求從零學完整的介面程式設計，也不提供老師的完整拍照程式當作業。

## 更新後先開新終端機

目前請使用最新 SQL（含 024）與工具 1.6.0。更新後關閉所有舊終端機，再開新的終端機；課程 mkdir/cd/ls/pwd/hostname 才會各自回報。學生使用的原指令不變。回報範圍、離線補送及本次／上次照片判讀見 [工作台說明](COURSE_MONITOR.md)。

## 學生操作

1. 首頁選自己的組別，進入「Python 與 USB 拍照」。原有資料夾、簡單 Python 與環境練習保留；操作位置檢查是選用。
2. 「用 AI 做拍照程式」顯示六項功能。學生自行決定如何向 AI 提問；網站不提供可直接貼給 AI 的提示詞，也沒有指定 AI 平台。
3. 在 Pi 的 Thonny 按 Ctrl+N，貼上 AI 的程式。按 Ctrl+S，存成網頁指定路徑，例如 `/home/user/pi-camera/pi5-01_camera.py`。不存到 Windows，也不貼到 Thonny 下方 `>>>`。
4. 按「開始試拍」，回 Pi 終端機執行網頁帶入本組完整路徑的指令，例如第 01 組是 `~/pi-course run -- /usr/bin/python3 /home/user/pi-camera/pi5-01_camera.py`。不加 sudo。程式不需要接收額外命令列參數。
5. 預覽、拍照，再按程式的「結束」。工具在結束後檢查新照片與相機，結果顯示在工作台。若出錯，複製本機錯誤給 AI 修改，儲存後重試同一行。
6. 用檔案管理員開啟照片，親眼確認清楚、完整，再下載到 Windows，準備之後的辨識課。

每組路徑：

| 項目 | 第 01 組範例 |
| --- | --- |
| 程式 | `~/pi-camera/pi5-01_camera.py` |
| 照片資料夾 | `~/pi-camera/photos/` |
| JPG 名稱 | `pi5-01_20261031_153000_123456.jpg` |

照片名稱固定為 `主機名稱_YYYYMMDD_HHMMSS_ffffff.jpg`；日期八位、時間六位、微秒六位，每次都用新的名稱，不覆蓋舊照片。第 02 組帶入 pi5-02，其他組依此類推。

## 拍照作業前：第 4 階段六項操作

在樹莓派遠端桌面的終端機執行。網頁每次只顯示一行，綠色按鈕複製完整指令。`~/pi-course run --` 後面是下表的實際指令；前綴讓這次執行能回報到老師的後台。

| 順序 | 實際操作 | 看見什麼 |
| --- | --- | --- |
| 1 | `sudo apt update` | 套件清單更新成功，回到輸入位置 |
| 2 | `sudo apt install -y v4l-utils python3-opencv python3-tk` | OpenCV、相機工具與介面套件安裝完成 |
| 3 | `/usr/bin/python3 -c "import cv2; import tkinter; print(cv2.__version__)"` | 顯示 OpenCV 版本；不要求固定版本號 |
| 4 | `v4l2-ctl --list-devices` | 找到 GENERAL WEBCAM 與可用的 USB 取像節點 |
| 5 | `v4l2-ctl -d /dev/video0 --list-formats-ext` | MJPG 下列出 1920x1080 |
| 6 | `v4l2-ctl -d /dev/video0 --all` | Driver、格式與控制項等資訊；只查看，不改設定 |

最後兩行的 /dev/video0 是範例：在網頁選擇本組上一行查到的取像位置，指令會同步帶入。開啟回報檢查時可依最新相機清單預選，手動模式仍可自行選擇。資料夾與組別切換時不借用別組選擇。中繼資料節點不會通過取像節點檢查。

每項有獨立的開始／成功／失敗與重試紀錄。解析度與設定查詢須對應同一個選定相機位置；換位置後需重新執行，不能只沿用另一個位置的舊成功。舊版 environment 的總結不等於新版六項已完成。

常見問題：找不到 cv2 就重做安裝並使用系統 /usr/bin/python3；沒有 GENERAL WEBCAM 就核對相機插在 Pi；沒有 MJPG 1920x1080 就保留結果請助教查看；下載失敗先確認熱點上網，安裝鎖定時等待其他安裝完成，不刪 lock 檔。列出的模式與 FPS 不等於已實測穩定取像，照片仍須實拍驗收。

## 最低功能

- 看得到 USB 相機畫面。
- 用滑鼠按「拍照」，保存相機實際取得的 1920×1080 JPG；不能只是放大小圖。
- 存到指定資料夾，檔名帶入本組名稱且不重複。
- 顯示成功、張數、照片實際尺寸與存檔位置。
- 有「結束」按鈕；結束後相機能再次使用。
- 相機未接、占用、讀取或存檔失敗時有提示，可重試。

網頁只列作業規範、設備環境、檔名與驗收方式，不提供提示詞或完整解答。預覽可以縮小顯示；不強制每次拍照重開相機或持續 1080P 的特定寫法。學生可請 AI 修正，但每種取像方案都要實機驗收。先拍照，不加入辨識、串流、Flask、YOLO 或新套件。

## 約 3～4 堂課

| 堂次 | 主要任務 | 驗收 |
| --- | --- | --- |
| 1 | 讀作業規範、自行向 AI 提問，存檔並啟動 | 看得到相機畫面 |
| 2 | 完成按鈕、存檔及提示 | 拍照、開啟 JPG、正常結束 |
| 3 | 修正錯誤、拍攝與整理物料照片 | 新照片通過技術檢查，畫面清楚完整 |
| 4（彈性） | 補拍、下載到 Windows、準備辨識資料 | 筆電能開啟照片 |

只需保留一次具體的「問題是什麼、請 AI 改了什麼」例子，不要求長篇心得、提示次數或解釋全部原始碼。評量以能操作、能依錯誤修改、能找到合格照片為主。物料類別、標註規則及辨識平台另由老師公布。

## 老師啟用

1. 資料庫管理者執行最新 [supabase/install.sql](../supabase/install.sql)，包含 **021_installer_permissions.sql**；不重建課堂。
2. 工作台「課堂工具 → 指派安裝／更新」選 **1.4.0**，依原核准流程更新各組 Pi。既有憑證、序號、待送事件、學生程式與照片保留；不要勾重新綁定，除非既有配對遺失。
3. 確認 Pi 的 Thonny 能開啟。環境沿用 apt 的 `v4l-utils`、`python3-opencv`、`python3-tk` 與系統 `/usr/bin/python3`；學生不另建 Pi 虛擬環境或安裝 pip OpenCV。
4. 先用測試機與隔離測試課堂驗收，再開放教材。正式九組 pi5-01～09 與 pi5-10 測試用途保持分開。
5. 「檢查通過後才能繼續」可開關。關閉時學生自行下一步，Pi 工具仍會回報；按下一步或複製指令不會產生設備成功。啟用後遇到檢查問題，仍有人工核對備援。

最新安裝檔含 021，提供修正版安裝器 1.4.0；舊安裝器有 root 暫存快取清理問題，請直接更新 1.4.0，不需逐版安裝。網站部署不會自動更新 Supabase 或學生設備。

## 自動檢查能證明什麼

網頁依組別帶入完整腳本路徑，課堂工具核對路徑必須是本機同組的指定程式，再用 user 執行，不是任意遠端執行服務。執行前保存照片清單，結束後檢查：

- 本組檔案確實被啟動，且程序結束碼為 0。
- 至少一張這次新增的照片；原有檔名即使重寫也不算新照片。執行期間不能更改或刪除舊照片。
- 所有這次新增的影像檔符合本組 JPG 檔名；每張可實際解碼為 1920×1080，不是只有副檔名正確。
- 程序結束後，由獨立且有逾時的相機檢查程序重新開啟 USB 相機，確認能取得影格，再釋放檢查用相機。

工作台分別列出「執行本組拍照程式」「儲存本次照片」「程式結束後重新取像」，必須來自同一次 run ID。舊版 camera_app.py 的成功不能通過新版作業。每項執行與重試沿用原回報序號及最近 10 次紀錄。執行中約 30 秒心跳；超過 90 秒沒有後續只標狀態待確認。

照片細項在程式結束後回傳，不是即時追蹤按了哪個按鈕。每次最多檢查 5,000 張既有照片，每張新圖上限 32 MiB；超過時請先由助教整理。需要保持照片資料夾不被其他程式同時修改。舊結果只代表上次檢查當下，修改後需重跑。

## 仍需人工確認

- 預覽看得到、介面按鈕與成功／錯誤提示好不好用。
- 照片清楚、曝光正常、物品完整，以及沒有只放大小圖或複製舊影像。固定名稱與尺寸不能證明原始影像來自相機。
- 「結束後可重新取像」不是驗證程式碼有寫出特定 release 語句，也不是安全或防作弊認證。學生程式以 user 權限執行，並非不可信程式沙箱。
- 在 Windows 找到並開啟下載的照片。Pi 無法證明筆電下載成功。

不監看任意終端機／Python 每一行，不上傳原始碼、完整 stdout、照片、縮圖或相機畫面。學生程式不需要讀取課堂憑證或自行呼叫網站 API。預覽、拍照張數、存檔提示與錯誤提示的介面顯示不會被工具自動驗證。

網路失敗仍保留有限待送事件；可用 `~/pi-course flush` 補送。新作業只在指定命令執行時檢查，不會因關閉網站而停止 Pi 程式；離開遠端桌面不等於正確關機。

## 實測範圍與現場驗收

老師先前在 pi5-10 確認 GENERAL WEBCAM／uvcvideo 的 /dev/video0 可用 MJPEG 預覽，儲存並開啟 1920×1080 JPG。裝置節點可能改變；商品自動對焦、原生感光元件解析度、長時間 30 FPS 與精確 OS 版本未確認。驅動版本 6.18.50 不視為 OS 版本。

舊版 `camera-install`／`camera` 及老師的 camera_app.py 保留供相容，這次不覆寫學生程式。它與學生 AI 程式是不同來源，不能把舊測試當成新程式已驗收。

- [ ] 實體 Pi 更新 1.4.0，既有配對、照片與雲端紀錄保留。
- [ ] Thonny、遠端桌面、相機預覽、按鈕、連續拍照、離開後重開皆正常。
- [ ] 新檔名、實際尺寸、照片品質；舊檔／錯組／破圖／覆蓋／異常結束均不會通過。
- [ ] USB 相機斷線、占用、重新插入時能提示與恢復，沒有卡住的子程序。
- [ ] 保留並查看 MJPEG 的 Corrupt JPEG data 警告；新檢查器不聲稱已統計或修復學生程式的警告。必要時另測 640×480 YUYV 比較。
- [ ] Windows scp、重複下載目錄層級及實際開啟照片成功。
- [ ] 手機、老師投影、關閉網頁後回報、斷網補送與手動備援由現場確認。

自動測試使用真實 Python 子程序、合成 JPEG、隔離資料庫與瀏覽器；不代替實體 Pi、USB 相機、Thonny、遠端桌面或 Windows 驗收。持續 1080P 取像、筆電模型推論及串流仍待後續測試與課程安排。

舊版短指令 `~/pi-course camera-student` 保留相容。新版完整路徑指令與它使用同一個檢查流程；不是將檔名放在註解裡，也不只是改顯示。錯組、其他 Python 檔案或額外參數會在啟動前拒絕。
