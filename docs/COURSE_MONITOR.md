# 工作台：各組課程操作與執行紀錄

工作台分為「首頁看板」與「詳細內容」：看板保留全班概況，詳細內容將組別選單與更新／登出整合在同一區塊，用下拉選單切換，也可從看板的查看本組直接進入。詳細分頁及組別可經由 `assistant.html?view=details&group=2` 直接開啟，仍須登入。查看不接手求助；只有明確按「接手並查看步驟」等操作才更新求助狀態。後台設定仍保留現有結構，另行討論整理。

## 畫面與判讀

- 看板：組別、目前回報的課程操作、實際結果、建議下一步。學生網頁位置另標「學生網頁」，不當成 Pi 執行證據。
- 組別：目前操作在左、狀態與最後回報時間在右；手機改為上下排列，右側狀態與時間並排。目前問題或操作放最前，成功項目維持一行，失敗、執行中或待確認項目展開；查看後的展開狀態會在更新時保留。設備資訊、求助與學生裝置紀錄分開收合。
- 重點：最新 Pi 回報項目用底色及文字標籤凸顯；執行中綠色、需處理淡紅、狀態待確認淡黃。學生網頁停留的階段另有藍色文字標籤，不能當成 Pi 已執行的證據。
- 操作：教材指令、已收到的檢查證據、錯誤分類、處理建議與執行紀錄。不顯示不存在的原始終端機日誌，也不會將舊成功蓋過新失敗。
- 失敗／中斷依每項最新結果判斷；本次重做成功才移除該項問題。本組程式、照片與結束後取像檢查需對應同一 run_id，才視為本課設備檢查齊全。
- 長時間沒有結束結果標示「狀態待確認」，不直接判定失敗或關機。成功只證明檢查當下；資料夾之後被刪除，需重做檢查。

## 啟用執行與重試紀錄

在 Supabase SQL Editor 執行最新的 [install.sql](../supabase/install.sql)，含 migration 017。維持同一份安裝檔，不需重裝 Pi 工具，也不要執行 create-classroom.sql。

資料庫從驗證後的 course_tasks 變更建立 course_runs；每組每項保留最近 10 次。只有查看本組時才讀取該組歷史，避免全班每 5 秒下載所有重試紀錄。重送與 heartbeat 不增加一次執行，也不改變最初開始時間。沒有 running 事件就不捏造開始時間。舊結果只匯入目前可用的一次；無法追溯升級前已被覆蓋的重試。

course_runs 啟用 RLS，不能直接從公開 API 讀取。教師 RPC 只允許該課堂有效帳號，學生 API 不新增歷史或私人 IP。一般工具更新沿用紀錄；舊版重新配對明確重設課程結果時，歷史一併重設。清除看板與求助不刪除 Pi 驗證紀錄。

尚未部署 017 時，最新檢查仍正常顯示，歷史區提供更新檔；讀取錯誤時保留舊證據並標示待確認。

## 後續課程接入原則

每個教材終端機操作都應有固定識別、對應指令、開始／結束事件與驗收條件，再納入共用操作清單。1.6.0 的互動 Bash 整合在原 shell 執行課程指定的 mkdir/cd/ls/pwd/hostname，再記錄結果。cd 不使用 Python 子程序假裝切換。若只有結束事件，開始時間明確標示未提供；不能從複製或點下一步推定執行。

目前不收集任意終端機歷史、不開放任意遠端指令、不上傳完整 stdout 或密碼；若後續需要更多錯誤內容，應先定義限定範圍與去除敏感資料的方式。

## 驗證

隔離資料庫：`PGLITE_ROOT=… node tests/run-course-history-sql.cjs`。

本機網站與隔離 Supabase 瀏覽器測試：`PI_HELPER_TEST_URL=http://127.0.0.1:8021/ PGLITE_ROOT=… node tests/run-group-monitor-browser.cjs`。涵蓋求助與查看分開、失敗重試、逾時、未升級後備、學生自行確認、320/390/768/1280 排版。不會寫入正式課堂。

仍需實際 Pi 5、教室網路與手機驗收回報及顯示；模擬測試不代表已完成硬體驗證。

看板卡片只保留最近 Pi 操作、建議處理、回報時間及求助狀態；服務詳情與學生裝置紀錄在詳細頁查看。自動檢查開關名稱為「檢查通過後才能繼續」，關閉僅解除學生進度限制，工具仍可回報。

## AI 拍照作業

新版需要 migration 018 及 Pi 工具 1.1.0，沿用同一份 install.sql 與指派更新，不新增配對。程式名依組別如 pi5-01_camera.py；實際執行名稱顯示在該操作的細項。程式執行中約每 30 秒回報，結束後才檢查本次新照片與相機可再次取像。不會將未驗證的預覽、按鈕或照片品質寫成通過。詳見 [拍照課程](CAMERA_COURSE.md)。

逐項環境回報需要 migration 019 及工具 1.2.0。`--list-formats-ext` 通過只代表選定 USB 取像節點列出 MJPG 1920×1080；`--all` 通過只代表唯讀查詢成功。兩者不是已取得清楚照片，也不表示自動對焦或長時間 FPS 已驗證。完整 v4l2 輸出保留在 Pi 終端機，後台只接收限定的結果與裝置路徑。

工具 1.3.0 的拍照教材改為完整路徑，例如 `~/pi-course run -- /usr/bin/python3 /home/user/pi-camera/pi5-01_camera.py`。operation ID 與 student_camera／photo／camera_exit 事件不變，後台仍保留原執行與重試紀錄；實際腳本名稱繼續列在證據中。

## 1.6.0 回報檢視修正

工具更新不會改變已經開啟的 Bash 視窗。若 `printf 'hook=%s\n' "${__pi_helper_loaded:-0}"` 顯示 `hook=0`，該視窗尚未載入回報；執行 `source ~/.local/share/pi-helper-course/course_shell.bash` 可在目前視窗啟用，再重做 mkdir/cd/ls。教材「建立資料夾」第 1 行已合併載入回報與 mkdir，沿用現有操作識別；不因資料夾存在而補造先前的指令紀錄。

先套用 install.sql（含 024），指派 1.6.0，完成更新後關閉所有舊終端機並開新視窗。新視窗會發出 terminal_ready，詳細內容顯示是否啟用；已有自訂同名 Bash 函式時不覆蓋，明確回報 hook_conflict。整合只處理互動 Bash 的固定課程指令，不讀取 history、PROMPT_COMMAND、密碼或任意指令；非互動 SSH、SCP 與腳本不受影響。

課程指令維持原樣；新增前述五項獨立紀錄及結束碼。舊 folders 成功不會補成 mkdir/cd/ls 已執行，升級前沒有收集的操作需重做才能有紀錄。沒有指定的新操作不會自動加入監控。Thonny 編輯、AI 提問過程、預覽介面、畫質與 Windows 下載維持人工確認，不能用全課程自行回報完成來標成每項設備驗證。

課程事件先以 0600 寫入本機佇列，再由 user 權限的單一補送程序送出；離線後不需再執行下一個指令才重試；重開機後登入桌面，課堂工具也會啟動補送。保留順序及第一次／最新的離線 heartbeat，最多 4096 筆，滿時明確警告，不默默捨棄舊資料。CLI 只有收到伺服器 true 才顯示已送達；資料庫版本、授權、網路問題分開提示。配對更新後補送程序重新讀取設定；同組更新沿用序號與待送事件。

每項證據附 Pi 記錄時間（設備時間），另保留伺服器收到時間；不以學生設備時鐘改寫收件順序。補送的歷史開始／結束時間明確標成收到回報時間。

照片驗證與結束後取像分開回報：照片合格而相機占用時，照片保留本次成功，相機項目顯示失敗；照片不合格也仍檢查相機能否再次使用。開始新一輪拍照後，上次照片／相機結果標示「上次結果，待本次驗證」，不繼續顯示為本次通過。

設備回報也修正套件查詢：hold 但實際 installed 的套件視為已安裝，查詢失敗顯示無法確認；不以任何 dpkg 非零回應都判定未安裝。這次因設備元件也更新，可能要求一次 Pi 密碼。

驗證包含真正 Bash 指令與 cd 狀態保留、離線／復連及順序、有限 schema、沒有假造開始時間、照片分項錯誤、320–1280px 瀏覽器顯示。正式上課前仍需 Pi 5／實際手機熱點驗收。
