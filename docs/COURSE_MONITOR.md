# 工作台：各組課程操作與執行紀錄

工作台採「全班概況 → 查看本組 → 單項執行細節」。查看不接手求助；只有明確按「接手並查看步驟」等操作才更新求助狀態。後台設定仍保留現有結構，另行討論整理。

## 畫面與判讀

- 看板：組別、目前回報的課程操作、實際結果、建議下一步。學生網頁位置另標「學生網頁」，不當成 Pi 執行證據。
- 組別：目前問題或操作放最前，成功項目維持一行，失敗、執行中或待確認項目展開；查看後的展開狀態會在更新時保留。設備資訊、求助與學生裝置紀錄分開收合。
- 操作：教材指令、已收到的檢查證據、錯誤分類、處理建議與執行紀錄。不顯示不存在的原始終端機日誌，也不會將舊成功蓋過新失敗。
- 失敗／中斷依每項最新結果判斷；本次重做成功才移除該項問題。相機預覽、照片與釋放相機需對應同一 run_id，才視為本課設備檢查齊全。
- 長時間沒有結束結果標示「狀態待確認」，不直接判定失敗或關機。成功只證明檢查當下；資料夾之後被刪除，需重做檢查。

## 現有回報範圍

| --- | --- |
| `~/pi-course folders` | pi-camera/photos 存在且可寫入 |

自動檢查開關控制學生能否自行下一步，並不停止既有工具回報。尚無紀錄不代表未操作；沒有工具、離線、未執行回報都可能造成缺少資料。

## 啟用執行與重試紀錄

在 Supabase SQL Editor 執行最新的 [install.sql](../supabase/install.sql)，含 migration 017。維持同一份安裝檔，不需重裝 Pi 工具，也不要執行 create-classroom.sql。

資料庫從驗證後的 course_tasks 變更建立 course_runs；每組每項保留最近 10 次。只有查看本組時才讀取該組歷史，避免全班每 5 秒下載所有重試紀錄。重送與 heartbeat 不增加一次執行，也不改變最初開始時間。沒有 running 事件就不捏造開始時間。舊結果只匯入目前可用的一次；無法追溯升級前已被覆蓋的重試。

course_runs 啟用 RLS，不能直接從公開 API 讀取。教師 RPC 只允許該課堂有效帳號，學生 API 不新增歷史或私人 IP。一般工具更新沿用紀錄；舊版重新配對明確重設課程結果時，歷史一併重設。清除看板與求助不刪除 Pi 驗證紀錄。

尚未部署 017 時，最新檢查仍正常顯示，歷史區提供更新檔；讀取錯誤時保留舊證據並標示待確認。

## 後續課程接入原則

每個教材終端機操作都應有固定識別、對應指令、開始／結束事件與驗收條件，再納入共用操作清單。要監看目前尚未支援的 mkdir/cd/ls，需要額外設計課程執行方式，不能只從瀏覽器複製或點下一步推定。尤其子程序中的 cd 不會改變學生原本 shell，不能直接用 Python 子程序包裝後宣稱已切換。

目前不收集任意終端機歷史、不開放任意遠端指令、不上傳完整 stdout 或密碼；若後續需要更多錯誤內容，應先定義限定範圍與去除敏感資料的方式。

## 驗證

隔離資料庫：`PGLITE_ROOT=… node tests/run-course-history-sql.cjs`。

本機網站與隔離 Supabase 瀏覽器測試：`PI_HELPER_TEST_URL=http://127.0.0.1:8021/ PGLITE_ROOT=… node tests/run-group-monitor-browser.cjs`。涵蓋求助與查看分開、失敗重試、逾時、未升級後備、學生自行確認、320/390/768/1280 排版。不會寫入正式課堂。

仍需實際 Pi 5、教室網路與手機驗收回報及顯示；模擬測試不代表已完成硬體驗證。
