# 樹莓派 5 課堂網站 v4

## 課程入口與求助提醒

- `index.html` 是課程首頁（舊 `course.html` 會導向首頁），先選組別，再直接進入 `student.html` 的刷機、SSH、遠端桌面與正確關機教學；組別會透過網址帶入並保留在本分頁。學生版與助教版皆有入口。
- Python、USB 相機與在學生筆電上辨識物品先列為待公布。Roboflow 僅為候選工具，尚未提供未確認的安裝或註冊步驟。
- 助教登入後，新的近期求助會在看板跳出對話框。使用排查工具、修改課堂設定或查看刷機圖解時會先保留提醒，回看板才顯示。
- 同一個助教分頁會記住已提醒的求助；自動同步不重複跳出，新一輪求助會再次提醒。「稍後處理」不會改變學生回報狀態，也不代表其他助教已處理。
- 基本求助通知沿用現有回報欄位；新增的共用接手清單需要執行下方升級 SQL。測試使用模擬課堂，不寫入正式課堂資料。

## 本版更新

- 每組卡片保留「協助此組」，可查看最後回報的階段、步驟、結果與時間。點「前往本組排查」會帶入正確組別與對應步驟；刷機則打開對應圖解位置。
- 幫助頁有「回到首頁看板」，工作區頂端也保留首頁看板入口。
- 圖解下方以醒目的「本組實際設定」列出 hostname、帳號、課堂密碼、地區、時區、SSH 與 Wi-Fi 要求。圖片僅供辨認欄位，不能照抄範例值。
- 助教登入後在課堂設定可儲存 1～99 組。學生組別、刷機組別、操作導覽、助教主機選單、看板與清除範圍一併更新。
- 主機名稱使用 pi5-01、pi5-02…pi5-99；刷機不加 .local，連線才加。

不提供虛構範例看板、額外的快速載入功能或 PDF；所有必要教學留在網站流程內。

## 上傳 GitHub Pages

將本資料夾的網站檔案與 assets/imager/ 完整覆蓋到儲存庫；本版新增的 **classroom-groups.js** 與 **flash-values.js** 都必須上傳。保留 config.js、responsive.css 與 .nojekyll。等待部署成功，再重新整理學生與助教頁面。

若儲存庫仍有更早版本的 course-guide.js、assets/handouts/ 或 TEACHING_REVIEW.md，請刪除。新版不再載入這些檔案。

目前使用的 Supabase 專案已完成組數升級，預設維持 9 組。組數功能不必重跑 SQL、不必變更密碼；本次共用求助與教材控制另需執行下方升級 SQL。supabase/update-group-count.sql 僅供其他部署升級；新專案可用最新版 setup.sql。

## 操作

1. 助教登入首頁看板，可在「共有幾組」填 1～99 整數並儲存；其他開啟的學生頁面約 15 秒內更新，另計網路時間。
2. 減少組數不會刪掉超出範圍的歷史回報；重新增加組數後可再查看。被移除組別的學生須重新確認組別，不能繼續回報超出範圍的組別。
3. 點組別下方「協助此組」查看目前步驟；無回報時會顯示等待學生開始，不假裝已有測試結果。
4. 圖解的主機名稱會隨所選組別更新。Wi-Fi 名稱與密碼必須讀本組手機的實際值；不要照抄圖片或把 Pi 密碼當熱點密碼。

## 驗證

執行 node tests/run-tests.cjs，無需安裝依賴。565 項程式與 DOM 模擬檢查通過，涵蓋兩端流程、組別幫助與返回、對應步驟接續、組數同步、清除範圍、刷機實際值與輸入限制。

正式 Supabase 已套用組數升級，並在臨時課堂以 anon 角色驗證設定讀取、教師驗證、1～99 組、減少組數保留歷史與回報範圍；測試已回滾。原有 2 筆課堂、7 筆回報、密碼與期限保留。

本版另以真實 Chromium 驗證 320、390、768、1280 px 排版與多助教操作；未使用實體手機或 Pi 驗證。看板顯示的是學生網站回報，不代表網站直接執行過 Pi 指令。

## 課堂功能（進度、求助與上課模式）

- 課程首頁可依本組、本瀏覽器記住上次步驟、自行確認完成的課程與設備檢查；可繼續或清除，不保存貼上的命令輸出與密碼。
- 每個步驟的「請助教幫忙」與 AI 整理分開。各組「協助此組」內支援接手、待學生確認、仍有問題與已處理；接手衝突不會覆蓋其他助教的結果。升級前仍可用既有回報通知助教看板，但不假裝有共用接手狀態。
- 助教版「課堂設定」可控制現有教材開放。關機教學保持開放；未公布教材仍不能開放。這是教學流程控制，不是靜態內容的保密機制。
- `presenter.html` 為老師上課模式，登入密碼只保留在該頁記憶體。支援步驟切換、示範組別、文字放大與全螢幕，並同步老師指定階段到學生首頁。
- **共用清單、教材開放與上課同步需管理員先執行 `supabase/update-learning-tools.sql`。** 已確認正式課堂可讀取共用課程設定；本次新增的個人帳號仍需另外套用下方帳號升級 SQL。可從 `classroom-setup.html` 下載。

開發檢查：`node tests/run-tests.cjs`。資料庫及完整瀏覽器流程可在 `/tmp` 安裝測試依賴後執行（不增加網站執行依賴）：

```sh
npm --cache /tmp/pi-npm-cache install --prefix /tmp/pi-pg --no-save @electric-sql/pglite
PGLITE_ROOT=/tmp/pi-pg/node_modules/@electric-sql/pglite node tests/run-learning-sql.cjs
# 先在另一個終端啟動 python3 -m http.server 8000 --bind 127.0.0.1
# 需要已有 Playwright 與 /usr/bin/chromium，或在測試檔調整瀏覽器位置。
PGLITE_ROOT=/tmp/pi-pg/node_modules/@electric-sql/pglite node tests/run-learning-browser.cjs
```

SQL 與瀏覽器整合測試使用隔離的 PostgreSQL（PGlite + pgcrypto）與測試課堂，不讀寫正式課堂。

## 工作台管理與個人登入

- 課前設備檢查預設收合，第一次刷機時再展開；原有勾選記錄保留。
- 工作台標題旁並排「立即更新／關閉看板」，手機亦維持同列。
- 依序套用 `supabase/update-learning-tools.sql`、`supabase/update-workbench-accounts.sql` 後，可用既有密碼登入管理員，在課堂設定新增各人的名稱與密碼。每人之後只需輸入自己的密碼。未升級時保留原有登入，明確顯示設定提示。
- 管理員可管理帳號；其他人可修改自己的名稱與密碼。接手求助自動使用登入名稱。密碼無長度限制，仍須填寫且不能與其他帳號重複。詳細設定及權限見 `SUPABASE_SETUP.md`。
- 新增隔離資料庫與 Chromium 流程測試 `tests/run-workbench-sql.cjs`、`tests/run-workbench-browser.cjs`。

課堂設定改為基本設定、教材開放、登入帳號、清除紀錄四個收合區塊。首頁看板移除共用求助清單，保留提醒對話框與各組「協助此組」。取消密碼長度限制須重新執行最新版帳號升級 SQL；既有帳號保留。

## 共用樣式與介面用詞

`site.css` 是各頁最後載入的共用樣式，統一配色、字體、按鈕、輸入欄位、卡片、導覽列與對話框。既有樣式保留教學流程、刷機側欄及老師大字模式的特殊版面。手動上傳時也須包含此檔。

首頁刪減重複說明；中文介面使用繁體中文與一致用詞，指令、軟體名稱、實際英文欄位及錯誤訊息保留原文供對照。登入帳號設定中的「管理其他帳號」與「新增帳號」各自獨立收合，兩者皆限管理員操作；這次介面更新不需要新增 SQL。

瀏覽器整合測試另驗證六個主要頁面在 320、390、768、1280 px 的共用外觀、繁體中文語言標記，以及帳號區塊可獨立開關。

## 學生求助回饋與操作圖片

求助送出成功即採用伺服器回傳狀態，操作頁上方及對話框皆顯示處理進度；每 5 秒更新，切回頁面或恢復網路時立即確認，也可手動更新。查詢失敗保留上次狀態；舊查詢不能覆蓋新送出的求助。重新整理會沿用同一裝置的 session 讀取既有求助，不會自動重送。

`operation-images.js` 在學生版、助教排查工具與老師上課模式加入 raspi-config、Windows 遠端桌面及 xrdp 登入的官方實際畫面。檔案放在 `assets/operations/`，使用無損 WebP、延後載入與點圖放大；來源、版本差異與授權見該目錄 `SOURCES.md`。帳號與目標以圖片下方的本組資料為準。這次不需要資料庫升級。

新增瀏覽器回歸測試：`PI_HELPER_TEST_URL=http://127.0.0.1:8001/ PGLITE_ROOT=/tmp/pi-pg/node_modules/@electric-sql/pglite node tests/run-help-feedback-browser.cjs`。先在儲存庫啟動 `python3 -m http.server 8001 --bind 127.0.0.1`；測試使用隔離資料庫，不寫入正式課堂。涵蓋實際定時更新、送出時舊查詢競爭、網路失敗、手動重試、回頁面更新、學生確認、重新整理恢復及圖片手機版。

## 持續協助與投影版面

關閉／稍後處理求助提醒只停止重複跳出，不代表接手或結案。看板各組卡片的「協助此組」可隨時重新進入，與提醒去重紀錄分開；同一登入帳號重新整理或重新登入後仍可使用。提醒內的「協助此組」也導向同一入口。

X11 對照圖改為三段：Advanced Options → Wayland → X11，可逐張切換與放大。圖像來源、擷取方式、版本差異及授權見 `assets/operations/SOURCES.md`。

老師模式的「全螢幕上課」使用專用投影版面：隱藏頁首，固定課程／組別／退出／上下步控制，教材區獨立捲動，有圖片時在寬螢幕圖文並排，窄螢幕改為上下排列。支援放大文字、Esc 還原及全螢幕中登出；登出後會忽略較晚回來的步驟更新結果；不支援 Fullscreen API 時仍可使用投影版面，並清楚提示。

`tests/run-projection-browser.cjs` 在隔離資料庫下驗證同帳號反覆協助、Esc 關閉提醒、原生全螢幕全部 30 步，以及 1920×1080、1280×720、1024×600、768×1024、390×844、844×390、320×568 的版面、放大、捲動與退出。這次更新不需要 SQL。

## 按鈕排列與回報可靠性

- 共用按鈕統一為 16 px 字級、24 px 行高、10 × 12 px 內距、10 px 圓角與至少 48 px 高度，集中覆蓋舊頁面的尺寸規則。求助卡片、課程續讀、學生輔助操作、刷機前後步驟與對話框採兩個等寬欄位，同組按鈕等高，長文字換行也不會使單一按鈕尺寸不同。窄螢幕看板標題讓出一列，避免縮小「立即更新／關閉看板」。
- 步驟回報只讓目前組別與最新版本的回應更新同步提示，避免舊請求失敗蓋掉新回報成功。送出求助前只送一次必要的步驟回報；網路恢復或回到頁面時立即補送最新狀態。
- 求助已寫入但回應遺失時，學生端會在後續查詢找回狀態，對話框直接顯示求助進度，不必重複送出。
- `tests/run-help-feedback-browser.cjs` 新增離線重試、舊失敗晚到、已送達但回應遺失的回歸檢查；`tests/run-projection-browser.cjs` 檢查求助按鈕在 320、390、768、1280 px 的排列與觸控尺寸。資料庫與瀏覽器檢查使用隔離課堂，不寫入正式資料。


## 清除看板時一併清除求助紀錄

舊版清除動作只設定進度回報的 `cleared_at`，沒有處理 `help_requests`，所以各組仍會看到以前的「已接手／待學生確認」。

1. 已完成共用課堂與個人帳號升級後，在同一個 Supabase 專案的 SQL Editor 執行 [supabase/update-board-clear.sql](supabase/update-board-clear.sql)。執行升級本身不會清空資料。之後若重跑舊的課堂或帳號升級，須最後再執行本修正。
2. 重新整理工作台，於「課堂設定 → 清除看板與求助紀錄」選擇單組或全班，再清除一次。成功訊息分別列出進度回報與求助紀錄的筆數。
3. 舊求助會移出所有工作台。學生約 5 秒內收到明確的清除通知，可用相同分頁重新求助；清除不代表問題已解決。仍在操作的學生可以重新回報目前進度，要保持空白看板請先關閉課堂。

清除採伺服器端歸檔，不刪除驗證學生所需的裝置憑證，也不影響帳號、密碼、組數或教材設定。新的單組／全班清除在同一筆交易完成，舊版本網站的清除 RPC 也會一併清除求助。未套用資料庫修正時，網站顯示「尚未清除」與更新連結，不以部分清除回報成功。

回歸檢查：`PI_HELPER_TEST_URL=http://127.0.0.1:8001/ PGLITE_ROOT=/tmp/pi-pg/node_modules/@electric-sql/pglite node tests/run-clear-board.cjs`。使用隔離課堂，涵蓋多裝置舊求助、單組／全班清除、其他課堂隔離、學生重新求助、舊請求不可復原已清除紀錄、舊版相容及缺少升級時的提示；不寫入正式資料。
